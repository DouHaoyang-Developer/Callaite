## 二、新增优化项明细（步骤 / 收益 / 风险）

### O10 长列表渲染与组件复用 ★ P1
- **问题描述**：列表全部使用普通 `ForEach`（78 处）且零 `@Reusable`；日志流（无限追加）、文件树（全量递归）、搜索结果（15 条×行组件）在大数据量下一次性创建全部节点，帧率与内存随数据规模线性劣化。
- **实施步骤**：
  1. 为三个长列表建 `IDataSource` 数据源封装（PageTree 扁平化队列 / JournalFeed 分页窗口 / SearchPanel 结果集）；
  2. 列表组件改 `LazyForEach`（键生成复用现有 ForEach 键函数）；
  3. `PageLink` / `NavRow` / 搜索行加 `@Reusable` + `aboutToReuse` 参数重置；
  4. 种子数据压测：注入 1000 页面 + 90 天日志，HiSmartPerf/Profiler 采滑动帧率，建立改造前后基线对比表。
- **预期收益**：千页规模滑动帧率 ≥55fps（基线待测）；列表内存峰值降低 40%+。
- **潜在风险**：① 树形递归结构与 LazyForEach 兼容性未验证——展开/折叠需数据源 `notifyDatasetChange` 精细化（避免整树重建）；② @Reusable 与 @Builder 混用的复用失效问题；③ 建议先在搜索面板（结构最简单）试点再推广。

### O11 启动与内存优化 ★ P2
- **问题描述**：`onWindowStageCreate` 同步串行初始化 21 个服务（图谱预热/订阅/账号/加密…），冷启动关键路径长；WebView 编辑器按块实例化，长文档多实例内存高。
- **实施步骤**：① 启动链分级：首屏必需（文件树/状态/主题）立即，其余（订阅/账号/图谱预热/云目录）延后至 `onWindowStageCreate` 完成后的空闲时机；② HiTrace 埋点分段计时，量化冷启动；③ WebView 多实例问题随 O4 编辑器重构自然消除（RichEditor 单实例），列为 O4 的附带收益。
- **预期收益**：冷启动 ≤1.5s（目标）；WebView 退出后内存峰值降约 30%。
- **潜在风险**：初始化时序变更——本项目有过"主题应用顺序错误导致资源限定符不切换"的前科（README 已记载），任何延后初始化必须逐项标注消费方与最早消费时点。

### O12 代码质量：大文件拆分与告警清零 ★ P2
- **问题描述**：Whiteboard.ets 1157 行（本会话已拆出工具栏/笔刷面板/状态栏三组件，剩余手势/绘制仍集中）；BlockView 787、SettingsPage 772；TODO/FIXME 36 处；编译 WARN 约 17 条。
- **实施步骤**：① Whiteboard 续拆（GestureHandler / PaintEngine 两文件）；② BlockView 行渲染与手势/菜单分离；③ TODO/FIXME 清单化：36 处逐条归类（实现/删除/转缺陷单），目标清零；④ `code-linter.json5` 已存在——接入构建脚本尾部作为门禁（0 error 才算过）。
- **预期收益**：单文件 ≤500 行的可评审性；告警清零降低上架审核风险。
- **潜在风险**：拆分 = 结构性改动，必须每步全量构建 + 平板冒烟（本会话曾因大块替换误删导航区——已记入教训）。

### O13 架构：AppState 瘦身与依赖显式化 ★ P3
- **问题描述**：AppState 594 行承载导航/历史/侧栏/主题/配置多域职责（God Object 倾向）；15 个 `getInstance` 单例构成隐式依赖网，无依赖图。
- **实施步骤**：① 按域拆分（NavigationState / SidebarState / ThemeState…），`@StorageLink` 键名不变的前提下内部重组（键名迁移成本高，**不动键**只动文件与职责边界）；② 产出单例依赖图（mermaid）入 docs；③ 明确不引入 DI 框架（ArkTS 限制下成本>收益，结论先行避免摇摆）。
- **预期收益**：O4/O6 大改造的爆炸半径减小；新人可读性。
- **潜在风险**：拆分过程中 @StorageLink/@Watch 时序敏感——必须保持"键名与写入时点"完全不变，纯物理搬移。

### O14 安全深化：同步冲突与桥接面收敛 ★ P2
- **问题描述**：① 云同步 last-write-wins 在双端并发编辑时静默丢一侧（v1 已列为风险，本版升级为正式项）；② WebView NativeBridge 的 `onAction` 无来源/命令白名单，编辑器 HTML 被注入时可伪造动作（虽内容已转义，桥面仍开放）；③ 权限面良好（仅 1 个 normal 权限，保持最小化 ✔）。
- **实施步骤**：① 同步冲突改"冲突副本"策略：检测到双端 mtime 均晚于上次同步点时，将较旧内容另存 `页面名.conflict.<日期>.md` 而非覆盖；② NativeBridge 加命令白名单（newBlock/save/indent/…固定集合，未知命令丢弃并 hilog 告警）；③ 隐私政策文案覆盖"笔记加密后上云"的既成事实描述。
- **预期收益**：并发零静默丢失；桥接攻击面收敛；上架合规。
- **潜在风险**：冲突副本增加用户清理负担（配冲突提示 UI）；白名单需与编辑器 JS 同步演进（版本绑定）。

### O15 测试与回归自动化 ★ P1（发布前置）
- **问题描述**：`ohosTest` 仅为 DevEco 模板骨架（Ability.test/List.test 无真实断言）；全部质量依赖人工走查——O1/O4/O6 三个大改造在无安全网下进行，回归成本与风险最高。
- **实施步骤**：
  1. **纯逻辑单测先行**（无 UI 依赖、可本地跑）：MarkdownParser 往返（md→树→md 不变式）、OutlinerEngine 17 种操作、QueryEngine/DatalogEngine、FSRS-4.5 调度、路径穿越清洗、WAL 重放（O1 完成后补测）；
  2. `hvigorw test` 接入 build_callaite.sh 尾部，失败即构建失败；
  3. 设备端集成冒烟固化：`uiwalk/walk.sh` + 关键页面截图 diff（本会话已有工具链，补阈值断言）；
  4. 关键路径集成测试：保存链（防抖→落库→落盘→WAL）、加密往返、同步冲突副本。
- **预期收益**：大改造安全网；发布前回归从"手工半天"降为"脚本 10 分钟"。
- **潜在风险**：模拟器不稳影响设备端测试稳定性——纯逻辑单测不受影响，设备端作为尽力而为层。

### O16 i18n 收尾 ★ P3
- 问题：本会话新增 UI（NewFileDialog 三选项文案/树统计行/活动栏方案等）硬编码中文，与既有 i18n 体系脱节。
- 步骤：① 硬编码扫描（grep 中文字面量于组件 build）→ 补 i18n.ets 键；② 双语走查一遍。
- 收益/风险：英文可用性 / 低。

### O17 无障碍补齐 ★ P3
- 问题：40vp 热区达标，但图标按钮缺 `accessibilityText`，焦点顺序未审。
- 步骤：图标按钮统一补语义标签（约 60 处）；TalkBack 抽查核心路径。
- 收益/风险：上架加分项 / 低。

## 三、优先级矩阵（影响 × 成本）

```
影响高 ┃ O1 数据   O2 稳定   O9a 签名      O4 编辑器  O5 活动栏  O15 测试
       ┃                                   O6 光感(GL) O8 验证
影响中 ┃ O10 列表  O14 安全  O9b AGC       O11 启动   O12 质量   O7 碰一碰
       ┃ O13 架构(部分收益在后续显现)
影响低 ┃ O16 i18n  O17 无障碍
       ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
         成本低            成本中                      成本高
```

**四象限结论**：
- **立即做（高影响×低中成本）**：O1、O2、O9a、O15、O5
- **规划做（高影响×高成本）**：O4、O6、O8 —— 必须先有 O15 安全网
- **见缝插针（中影响×低中成本）**：O10、O14、O12、O9b、O11
- **择机做（低影响）**：O16、O17、O13

## 六、v1.0 方案审查：不明确与矛盾点及修订（本版核心增值）

| # | 问题 | 类型 | 修订决定 |
|---|---|---|---|
| 1 | O1 表述"落盘依赖 onBackground"与实际不符（实际存在失焦保存+防抖落库，落盘确实仅在后台/关闭时机） | **事实性偏差** | O1 修正为两层：页面级快照 WAL（覆盖"未落盘窗口"）+ 版本号保存队列；WAL 重放对象 = 上次落盘后的页面快照流 |
| 2 | v1 称 O4 与 O6"并行可行（不同模块）"，但两者都落点于 ContentArea/PageView 文件 | **矛盾** | 改为**外壳先行**：GL-2 主壳迁移（W2）→ O4 编辑器在新外壳内落地（W4）；如需并行必须分支隔离并明确合并顺序 |
| 3 | InstantShapeEngine 白板增强 vs 用户此前明确排除"白板原生形态复刻" | **潜在范围冲突** | 区分"形态复刻（用户已排除，不做）"与"笔迹能力增强"；增强项标注**仅在用户再次确认后启动** |
| 4 | "UI 还原度 ≥90%" 无测量定义 | 不明确 | 引入四维评分法（见验收标准 #6），评分表随 M2 产出 |
| 5 | GL-4 底部栏"评估迁移 Tabs 或保留自绘"二选一留白 | 不明确 | 决策规则：GL-2 完成后若 TabBar 迁移成本评估 ≤3 天走 Tabs 原生（材质/模糊全托管）；否则自绘 + 仅接光效，并在 GL-4 开始前48h 内定案 |
| 6 | 6 周排期未标注外部依赖等待（AGC/签名/真机） | 不明确 | 外部依赖清单：①AGC 项目（用户操作，M2 的 O8a 前置）②发布证书（用户操作，M1 的 O9a）③双真机（O8b 前置）——任一延迟直接顺延对应链路，关键路径 = O9a→O8a→O8b |
| 7 | Lunius 移植未计适配成本 | 不明确 | 明确适配工作量：每组件 +0.5 天（token 替换/热区对齐/三态动效统一），已在 W4 排期中体现 |
| 8 | O2 THREAD_BLOCK 未排除模拟器自身因素 | 不明确 | O2 增加真机对照步骤：若真机不复现，降级为"模拟器已知问题"并记录，不阻塞发布 |
