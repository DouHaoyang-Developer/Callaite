### 2.1 结构 — **1.5 / 2**

**加分（改造确实带来了结构收益）**
- 三条改造点在结构上全部落地：双列导航收成「1 Ribbon + 1 面板」（省下 44vp 全部让给面板）；面板顶部有了视图切换器；设置左列有了搜索框和两个分组标题。这正是 Obsidian 的左区结构骨架（Ribbon + 单面板 + 面板内头部）。
- `CHG-02` 证明切换器不是装饰：面板主体整块替换。

**扣分**
1. **设置页仍是「页」而不是「模态」。** Obsidian（Laptop 12）的设置是悬浮圆角卡片、标题栏居中、右上 ×。Callaite 的设置在标签栏里是一个标签页（`设置 ×`），页内用「← 设置」返回。这带来两个副作用：一是设置会占用一个文档标签位，二是存在「←」和标签「×」两个语义重复的退出入口。
2. **右列完全没有 Obsidian 的「加粗标题 + 灰说明小字」结构。** 见 §4-1。
3. **侧栏的「面板」没有 container 语义**：`CHG-03` 打开设置时，面板只剩 chip 行 + 搜索框，下方 260vp×715vp 完全空置，没有任何占位或收起逻辑（`dumpq.py CHG-03 tree --max-x 620` 在 y>226 后无任何节点）。
4. **导航入口重复**：`搜索`、`书签` 在 Ribbon 里有图标项，在 chip 行里又各有一个 chip（Ribbon 第 2 项放大镜 = 搜索；chip 第 2 项 = 搜索；chip 第 3 项书签 = 星形 ☆）。W1 的目标是「活动栏入口迁入 Ribbon」，但迁移没有做去重。

**扣分（均带数值）**

### 2.5 任务书点名的四个重点问题

**(1) 侧栏宽度与 Obsidian（240–260px）的关系**
实测 Obsidian 参考图侧栏叶宽是 **300px**（x=44..343），不是 240–260px。Callaite 改造后为 260vp（含滚动条槽 264vp）。
- 若以任务书给的 240–260px 为基准：**260vp 正好压在上沿，判定合格**。
- 若以参考图实测的 300px 为基准：**窄 36–40px（约 12–13%）**，在「所有页面」这类内容型视图下会显得列表更局促。
- 差异来源不确定（见 §5-U1），**建议以参考图实测的 300px 为上限、260vp 为下限，把面板调到 270–280vp** 更稳妥。

**(2) 视图切换器与 Obsidian 侧栏顶部的关系**
- Obsidian 侧栏顶部是**视图自己的操作图标行**（新建笔记 / 新建文件夹 / 排序 / 收起，Laptop(2)(3)(13)(14) 均为一行 4–5 个图标），**没有视图切换器**；换视图靠点 Ribbon。
- Callaite 在面板顶部放的是一行**视图切换 chip**（文件/搜索/书签/标签），并把 Obsidian 那种操作图标挤成了尾部的两个按钮（`y=85 x=524`、`x=584`）。
- 结构上这是**两种不同的解法**，不是「像/不像」的问题。Callaite 的写法在平板（触屏、无 hover）上更好懂，可以保留；但需要修掉 S-1（选中态）和 S-5（越界），否则这一行同时存在「看不出当前视图」和「按钮出界」两个硬伤。

**(3) 设置页左列分组与「搜索设置」的形态**
- **分组标题：形态已对齐。** 「选项」「扩展与信息」都是小号灰字、位于组首，与 Obsidian 的「选项」「核心插件」同类（Laptop(12)：组内项节距 27px，跨组 80px）。但**强度不足**：Obsidian 跨组多留 53px，Callaite 只多留 12px，分组感偏弱。
- **搜索设置输入框：形态相反。** Obsidian 是**白底 + 1px 描边 + 左侧放大镜图标**（`probe.py Obsidian_Laptop(12).png v 900 360 470` → y=386..388 与 y=417..419 各有一段 `(189,189,189)` 边框，中间 28px 白色内胆；左侧有放大镜）；Callaite 是**无边框的灰底填充** `#E3E5E8`，**且没有放大镜图标**（`y=398 x=636 w=268 h=64 TextInput`，无子图标节点）。
- 尺寸上 Callaite 134×32vp 偏扁；Obsidian ≈187×34px（模态内）。
- **结论：分组做到了，搜索设置的「可识别性」没做到** —— 无图标 + 无描边时，它更像一个只读的灰条而不是输入框。

**(4) 设置内容顶对齐是否解决「内容垂直居中、上方大片空白」**
**解决了，且有硬数据**：右列 8 个元素整体上移 **307px = 153.5vp**（主题 689→382 … English 1386→1079），改造前「主题」位于内容区中部、上方约 265px 空白，现在「主题」直接贴到右栏顶边。

## 5. 诚实登记不确定项

- **U1（影响最大）｜Obsidian 侧栏 300px 是默认值还是被拖宽过。** 我从四张参考图实测侧栏叶宽都是 **300px**（`x=44..343`，四张完全一致），而不是任务书给的 240–260px。Obsidian 的侧栏宽度是**按仓库记忆**的用户可拖拽值，所以「参考图里的 300px」可能是这个仓库被调宽后的状态，而 Obsidian 的出厂默认可能确实在 240–260px。我的尺度标定（1px≈1 CSS px）有三条独立证据支撑（标签栏 40px、CJK 字高 12px、Ribbon 44px），但**无法从图里证明 300px 就是默认值**。→ 结论中的宽度对比请按「参考图实测 300px」与「任务书 240–260px」两个基准分别看；我在 §2.5(1) 给了两种判定。
- **U2｜Ribbon 第 9 项（y=794，accent 高亮）是什么功能。** dump 只有 `Path`/`Shape` 节点，不携带图标语义；放大图里它是「两个层叠的文档」形状。无法仅凭图判断它是「所有页面」「分屏」还是别的，因此 S-10 只能报告「两个高亮同时存在」这一事实，不能断定哪个是误高亮。
- **U3｜Obsidian 模态窗的精确宽高与内部边距。** Laptop(12) 的模态底色是白色，与背后同样是白色的编辑器/图谱区在多数 y 上无法用颜色区分边界，我只在 y=1150..1250 扫到内部 1px 分隔线（x=1451）。因此「设置左列 ≈210px」「模态 ≈903×727px」是**估读值**，未做像素级确认；本文未把它们作为评分依据。
- **U4｜「最近」列表的排序规则。** `CHG-01` 中最近为 Home / 未命名 3 / 未命名笔记 / 未命名 4 / 未命名 5 / 未命名 2，非字典序；而 `2026-09-19`、`2026-09-25` 两个文件不在其中。推测是「最近打开」，但**无法从截图证实**，故未作为问题记录。
- **U5｜设置右列各行的实际交互。** 「浅色/深色/跟随系统」三行都有**完全相同的圆形图标**（均为 `Shape 32×32` + `Path 64×64`），从 dump 无法确认它们是主题预览色块还是普通项目符号；截图（`rev_chg03_rightcol.png`）里三者肉眼同形。若原意是「三个主题小预览图」，则这是一个渲染失败的图标（已在 §2.3-4 记一笔）。
- **U6｜S-2 空洞的成因是推断而非实证。** 「文件树块被垂直居中」的结论来自 `(容器高 − 内容高)/2 = 上空隙 ≈ 下空隙`（202 vs 201）这一吻合，而非来自源码。也可能有别的成因（例如内容被包在一个 `height:100%` + `justifyContent:Center` 的 Column 里，或存在隐藏的等高空节点）。**请以「109vp 空洞确实存在」为准，「居中是原因」为推断。**
- **U7｜改动前的基线取自 `05-Home_dump.json` / `70-Settings_dump.json`。** 这两个 dump 与 CHG 系列之间**是否夹了其它改动**我无法确认，因此 W1-b（216vp→260vp）、S-2、S-3 的「改造前」数据只能作为**同一仓库、较早时点**的参照，不保证是紧邻的上一个版本。
- **U8｜`CHG-01` 与 `CHG-03` 的侧栏视图状态是否真的都是「文件」。** 我依据的是面板内容（CHG-01 有收藏夹/最近/文件树）与 chip 高亮（CHG-03 高亮「文件」）。CHG-01 无高亮，所以严格说 CHG-01 的「当前视图 = 文件」是由**面板内容**推断的，不是由选中态读出的。
