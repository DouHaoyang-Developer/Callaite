### 1.5 CHG-08「没有属性区」的判定（关键澄清）

**该截图不是单日页，也不是普通页，而是 JournalFeed（日志流首页）。** 三条硬证据：

1. 首个日期标题「2026年9月25日 星期五」行盒 `[790,238] 1920×112` = 56vp。JournalFeed 的标题是 `fontSize(24)` + `padding{top:20,bottom:8}` ⇒ 24×1.2+28 = **56.8vp ✓**；而 PageView 的页面标题是 `fontSize(36)` + `padding{top:20,bottom:8}` ⇒ 71.2vp = 142px ✗。
2. 该标题 dump `clickable=true`，与 JournalFeed 的 `Text(...).onClick(() => AppState.setCurrentPage(day))` 一致；PageView 的页面标题没有 onClick。
3. dump 含 **4 个日期段**（9/25、9/24、9/23、9/22 起头），是 `ForEach(days)` 的滚动时间流形态。

因此：

- **「此页没有属性区」＝正确表现**，但理由不是"该页无属性"，而是**这个组件本来就不渲染属性区**。`JournalFeed.ets` 全文无 `Propert` / `属性` 任何匹配；属性区只存在于 `PageView.ets` 的普通页面分支。
- 所以本图**不能**用来证明「空属性时整块隐藏」这条逻辑。要验证该逻辑必须打开**单页**（PageView 普通页面分支）。
- **属性区出现的完整条件**（源码 `PageView.ets` L92–L124、L164–L169、L229–L279）：
  1. 当前页不是 `Settings / Journal / Graph / Whiteboards / Flashcards / Pdf / ProUpgrade / Home / AllPages / Recycle / About` 之一（走 `else` 分支）；
  2. `pagePropKeys.length > 0`，即 `WorkspaceService.getPageByName(displayName)` 能解析到页面，且 `page.properties` 至少 1 条；
  3. 另有一个**潜在陷阱**：当 `this.page() === 'Journal'` 时 `displayName` 被置为「今天的日期字符串」，属性查找用的是这个日期字符串键；若某天的日志页键名与 `getTodayDateString()` 不一致，属性查不到 → 属性区静默消失（无法从截图证实，属代码阅读结论，见 §5）。
  4. 属性区**只读**（注释 L226–L227 明示"仅展示，不做行内编辑…此处不新增输入控件"），且空属性时没有任何「添加属性」入口 ⇒ **用户无法在页面里创建第一条属性**。
- 与 Obsidian 对比：Obsidian 1.13 对**无 frontmatter 的笔记同样不显示属性块**（参考图 `Laptop(1)` 的「2026-09-19」正文只有标题），所以在"隐藏"这一点上与 Obsidian 一致；差异在于 Obsidian 有命令面板「添加文件属性」与 `---` 手写两条补录路径，而 Callaite 的页面内补录路径在本次截图中**看不到**（不确定其属性面板入口，见 §5）。

### 1.6 CHG-09 无效样本的确切原因（值得记一笔）

- 截图实际页面：**`ProUpgradePage`（Callaite Pro 升级/对比页）**。标题 `Text('Callaite Pro') [764,294] 264×56`（24vp 粗体），页签文本 `[2323,103]` 也是「Callaite Pro」。
- 全文检索「复习」「开始复习」→ **0 命中**；唯一含「闪卡」的节点是对比表行 `Text('闪卡系统') [700,649] 1860×33`。
- 原因（源码）：`Ribbon.ets` L83–L84 与 `LeftSidebar.ets` L523–L524 —— 非 Pro 状态下点击「闪卡」会 `canUseFeature('flashcard')` 失败并**重定向到升级页**。本次采集设备的 `SubscriptionService.isPro === false`，所以点了闪卡进来的是 Pro 页。
- 真正的闪卡页存在（`FlashcardPage.ets` L103 `Button('开始复习')` + `buildStatsCard()`），但**本次拿不到有效样本**。
- 附带发现：`Button('开始复习')` 出现在 `buildFinished()`（"今日复习完成"分支）里，而不是有卡可复习的初始态；`buildCard()` 分支没有任何主 CTA。即真实运行下，"有卡待复习"时看不到「开始复习」。这是代码阅读结论（无截图可验证）。

## 3. 新发现问题（含 dump 数值）

### 3.1 设置内容块在窗格内水平居中，与左导航之间留 110vp 死区（CHG-04）

- 内容窗格：`x 920 … 2880`（窗格中心 1900）

### 3.2 「名称 ↑」是无效 affordance（CHG-05）

### 3.4 页签名与内容范围不符（CHG-08）

页签 = 「2026年9月25日 星期五」（`[785,103] 269×30`），内容却是连续时间流（含 9/24、9/23、9/22 三个后续日期段）。建议页签名用「日志」类泛称。

### 3.5 图谱 canvas 单位混用（CHG-07）

- 节点坐标按 **vp**：团中心实测 (1737,1134)，画布中心 (1750,1133)，偏差 13px ⇒ 布局坐标与 vp 画布一致。
- 标签字号按**物理 px**：源码 `ctx.font = '11px sans-serif'`，实测 CJK ink 9–10px（若为 11vp 应为约 20px）⇒ 实际 ≈ 5.5vp，比同屏最小的 UI 文案（11vp，实测 ink 19px）还小 53%。
- 附带风险：`ctx.clearRect(0, 0, w, h)` 传入的是 vp 尺寸（1130×679），若 `clearRect` 同样按物理 px 解析，则只清掉画布左上 1/4 —— 在首次绘制时看不出，一旦平移/缩放就可能残留。**未在本批静态截图中复现，标为待验证。**

## 4. 仍存在的差距

1. **行内编辑缺位**：属性区（`PageView.PropertiesSection`）与 PDF 导入都只到"展示/提示"为止，没有落地操作；属性区连"添加第一条属性"的入口都没有。

5. **日期层级信号过弱**（CHG-08）：今天与其他日期只差 15% 透明度（实测最暗 0 vs 40/42）。
6. **设置分组容器缺失**：Obsidian 的"浅灰底 + 白色圆角分组卡片"结构没有对应实现（本页为纯白底 + 线）。
7. **栅格不统一**：5 套内容左内缩（§3.6）。
8. **删除能力在「所有页面」不可达**（§3.8）。

### 附：本次使用的查询/实测手段

- `find_node.py <dump> --list / <文本> --props`：取节点 bbox（px 与 vp）、`backgroundColor`、`clickable`
- `dumpq.py`（本会话新建，`json.load` 递归）：`tree`（按 y 排序列节点）/ `text`（子串匹配全命中）/ `node`（打印完整 attributes）/ `bg`（按背景色全量过滤）/ `bgs`（颜色直方图）
- `blobs.py`（本会话新建）：区域内暗像素连通域 ⇒ 得到**字号 ink 高度**与圆点直径（dump 不提供字号，这是唯一可靠途径）
- `crop.py`（本会话新建）：局部裁切放大后目视核对（描边、胶囊底色、按钮层级）
- dump `attributes` 实际键：`accessibilityId, backgroundColor, backgroundImage, blur, bounds, checkable, checked, clickable, clip, description, displayId, enabled, focused, hashcode, hierarchy, hint, hitTestBehavior, hostWindowId, id, key, longClickable, opacity, origBounds, originalText, scrollable, selected, text, type, visible, zIndex`（**无 fontSize / fontColor**）

### 附：Canvas 内图元不在 dump 内

`Canvas` 的绘制内容（节点圆点、连线、标签）**不会**出现在布局 dump 中（CHG-07 的 dump 在画布区域只有一个 `Canvas` + `Stack` + 右下角控件）。因此图谱的图元数量/尺寸结论**全部来自像素实测**，不是 dump 读取。
