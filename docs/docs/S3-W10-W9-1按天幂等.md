## 2. 判据的设计决策（**本窗口唯一的设计决策** ✗✓）

### 2.1 结论：**「以模板文本开头」的顶层块 ⇒ 算「今天已经插过」**

| 子决策 | 选择 | 理由 |
|---|---|---|
| 相等 vs 前缀 | **前缀**（`existing.startsWith(...)`）| 用户当天把 `📌 今日要点: ` 改写成 `📌 今日要点: 写完 W10` 之后，**它仍算今天已插过** ✓ —— 否则同一天会**再插一次**（正是本缺陷的用户可见形态 ✗）；**次日是新页** ⇒ 自然再插一次 ✓（「每天一次」语义保住 ✓）|
| 用哪个串做前缀 | **`content`（不含 marker）** | 模型里的 `content` **不含 marker**（§1.3）⇒ 用含 marker 的串**命中恒为 0** ✗（实测）|
| 尾随空白 | **两侧都归一**（`content.trimEnd()`）| 入参带尾随空格、模型里已被剥掉（§1.3）⇒ 不归一则**守卫失效** ✗（实测）|
| 多行模板 | 除首行形态外，再匹配**续行形态** `'\n  - '` | 3 行模板落盘再解析后，第 2 行起被写成 `'  - 行'`（`MarkdownExporter.ets:73-77` + `INDENT_PREFIX='  '`）⇒ 只匹配首行会让多行模板**当天仍重复插入** ✗（Ⓒ 差分夹具 J 实测 ✓）|
| 替换方式 | **`split('\n').join('\n  - ')`** 而不是 `replace` | `String.replace` 传字符串**只替换第一处** ✗ ⇒ 3 行模板只转换 1 处 ⇒ **J 夹具判负**（Ⓒ 实测：`inserted=1` ✗）；换成 `split/join` 后 **J ⇒ `inserted=0`** ✓ |
| 作用域 | **只查顶层块**（`ws.getPageBlocks` = `getTopLevelBlocks`）| 本方法**自己也只插顶层块**（`parentId: page.uuid`）⇒ 与插入位置**同域** ✓；子块里的同款文本**不参与**判据（不会误拦）✓ |
| 数据源 | **内存模型**（非磁盘）| 与 `PluginAPI.getPageBlocks()` 同一通道 ✓；本页若尚有「已改但未 flush」的文本，判据看到的是**内存值**（本仓一致口径 ✓）|

### 2.2 判据的**已知代价**（刻意偏保守 ✓，写清楚备查）

1. **用户手打**一行以同模板开头的块 ⇒ **当天不再插** ✓（这是**想要的**语义：它就是「今日要点」行 ✓）。
2. **用户当天把模板整行删掉** ⇒ 判据失效 ⇒ **会再插一次** ✓（合理：那一天确实没有该行了）。
3. **`marker` 的语义**：修复后写进模型的串仍是 `'TODO 📌 今日要点: '`（**与修复前逐字节相同** ✓ Ⓒ 夹具 K）
   —— 落盘、下次解析后 marker 被剥进 `block.marker` ⇒ 这是**既有往返行为**，本窗口**未改** ✓。

### 2.3 语义是「**每天一次**」而不是「**永不**」✓

- **每次冷启动**都会进 `insertTodayBlock` ✓；**当天已有 ⇒ 不插** ✓；**次日换页 ⇒ 照插** ✓
  （`getPageByName(today)` 的 `today` 来自 `new Date()` ✓）。
- ⇒ **代码现在符合它自己的注释**（`BuiltinPlugins.ets:12`：「**每天**自动在日志页插入快速记录模板」✓）。
- ⚠️ **本窗口没有实测跨日切换** ✗（改系统时钟代价与风险都大，未做）⇒
  「次日会再插」是**代码级推论**（Ⓑ）+ **Ⓒ 差分夹具 A/G**（空页 / 无占位块的页 ⇒ 两版都插 1 块 ✓）支撑 ✓。
