### 1.5 根因（代码级，已定位到行）

`entry/src/main/ets/components/outliner/BlockEditor.ets`：

| 位置 | 内容 |
|---|---|
| `:973` | `.onKeyPreIme((event: KeyEvent): boolean => { … return this.routeKeyPreIme(event); })` |
| `:581` | `private routeKeyPreIme(event: KeyEvent): boolean` |
| `:589-592` | `// ─── Enter / 小键盘 Enter ⇒ 见 routeKeyEnter …` → `return this.routeKeyEnter(event);` |
| `:747` | `private routeKeyEnter(event: KeyEvent): boolean` —— 行中插 `\n`、末尾 `create-below`，**两条分支都 `return true`（已消费）** |

**机制**：SDK 的事件顺序是 **`onKeyPreIme` → `keyboardShortcut` → input method events → `onKeyEventDispatch` → `onKeyEvent`**（W5 自己在 `:426-428`、`:450-451` 引了原文）。
`onKeyPreIme` **早于输入法**，返回 `true` 之后**连 input method events 一起被拦**（`common.d.ts:18672-18687`）
⇒ **组词态的回车根本到不了输入法** ✗。

**为什么 W5 会漏掉这条**（W8-5）：`BlockEditor.ets:730-745` 的注释**已经写出了这个风险**，
然后以「**输入法消费掉的键不会到达应用的按键回调**（W11 实测：拼音字母键 0 次进入路由器）」为底气把它排除。
但这条机制**只对 post-IME 回调成立** —— 同一个文件 `:442-448` 正是**基于同一理由**把 `↑↓/Backspace` 放在 post-IME、把 `Tab` 留在 preIme。
**:453-455 与 :735-737 把「post-IME 的旁证」用在了「pre-IME 的落点」上** ⇒ 前提失效 ✓

> ⚠️ **本窗口没有改这一行** ✗（硬约束 1：可能不需要改业务代码 —— 但这里是**需要改**的，
> 只是修法涉及按键归属的取舍，属**架构决策**，应由上级裁决后另开窗口）。
> **候选修法（仅登记，未落地、未验证）**：组词态守卫。W11 在 A 形态用过
> 「回车改走 `TextInput.onSubmit` + `reportImePreviewText` 上报 IME 预览文本」这一路

## 8. 对上级的提示

1. ★ **判据④ 在 2in1 上判负，且根因是 W5 的 Enter 接管** ✗（§1.5）——
   这是 S3 的**出口条件之一**（D-Gate 1 判据④）落在 **B 形态**上**没有满足**。
   **换包这一动作是必需的**：不换包装的就是 W11/W12 旧包，测出来会是"通过"（假绿）✗
2. **修法属架构决策，建议上级裁决后再开窗口** ✗：`onKeyPreIme` 上拦 Enter 与"输入法优先"在**原理上互斥**
   （preIme 就是早于 IME）。可选方向：
   ① 把 Enter 也移到 **post-IME**（W5 §3 已实测"太晚"：native 会先插换行并报 `spanIndex error`）；
   ② 组词态守卫（W11 在 A 形态用过 `onSubmit` + 预览文本上报，但 `RichEditor` 没有该通道）；
   ③ 折中：**只在"能确认不在组词态"时**在 preIme 拦。**三条都未验证** ✓
3. **"注入键是否过 IME"必须先确认编辑器有焦点** ✗（W8-8）——
   无焦点时注入**毫无反应**，极易被误判成"设备/通道坏了"（与 W6 的坐标误判同类）。
   **建议把这条补进 AGENTS 陷阱 21 的行动规则** ✓
