## 1. 目标

**复现并修掉两条数据完整性缺陷**，二者同族（都是「**声称成功但磁盘上没有**」）：

| 编号 | 名称 | 一句话 |
|---|---|---|
| **N1-a** | **写入失败被吞** | 落盘失败**不抛异常、不返回失败**，却被**三层调用方一致当成成功** ⇒ 脏页被清除、**永不重试** ⇒ **静默永久丢内容** |
| **N1-b** | **重命名丢页** | `renamePage` 是「**先删旧文件 → … → 最后才写新文件**」且**无原子性、无回滚**；叠加 **N1-a** ⇒ 旧文件已删、新文件没写、界面显示成功 |

### 1.1 为什么它排在 UI 冲刺之前

这不是「UI 不好看」，是**类**（class of defect）：**任何一次落盘失败都会静默变成永久数据丢失**，而失败面覆盖**全部**经过 `savePage` 的路径（惰性链 + 即时链，见 §3.2 的链路图）。UI 冲刺要动四屏外壳，其中 W6 明确要动 `ContentArea`（编辑器主径）⇒ **必须先把「写盘失败会不会被吞」这件事钉死** ✓。

```ts
writeTextSync(path: string, content: string): void {      // ← 返回 void
  const tmpPath = path + '.tmp';
  try {
    const file = fs.openSync(tmpPath, ...);
    fs.writeSync(file.fd, content);
    fs.fsyncSync(file.fd);
    fs.closeSync(file);
```

```ts
/** @returns 是否确实写盘成功。失败时由调用方（DirtyPageTracker）重新标脏，…避免「写失败即静默丢弃」。 */
persistNow(pageId: string): boolean {
  if (!this.dataStore.getPage(pageId)) { return false; }
  try {
    this.dataStore.savePage(pageId);
    return true;                       // ← 写失败也走到这里
  } catch (e) {
    console.error('[OutlinerEngine] persistNow failed for page ' + pageId + ...);
    return false;                      // ← 这条分支对写盘失败是**死代码**
  }
}
```
