## 2. 归因（**硬证据**）

### 2.1 第一步：先证伪「日期枚举无界」

`JournalFeed.appendDays()` 自带两条闸（上限 `MAX_JOURNAL_DAYS=180` + 500 ms 节流），
且**每一步都打 hilog**（`APPEND` / `APPEND_DONE` / `SKIP` / `NO_MORE`）⇒ **这是一条不需要 a11y 的证据通道** ✓✓
（本问题的 a11y 通道正好被压垮，所以这条通道是关键）。

**清空 hilog 缓冲 + 冷启动后读回**（前后共 4 次冷启动，结论一致）：

```
10-02 18:12:28.683  10092 10092 I A00000/JOURNALFEED: APPEND days=7 from=2026-10-02 total=0 today=2026-10-2
10-02 18:12:28.683  10092 10092 I A00000/JOURNALFEED: APPEND_DONE added=7 total=7 newest=2026-10-02 oldest=2026-09-26
```

| 观测 | 值 | 含义 |
|---|---|---|
| `APPEND` 次数 | **1** | `aboutToAppear` 那一次；`onReachEnd` **一次都没触发** |
| `APPEND_DONE total=` | **7** | `days.length === 7` —— **不是 180** ✗ |
| `SKIP` 条数 | **0** | 节流闸没有拦下任何东西（= 没有第 2 次触底） |
| `NO_MORE` 条数 | **0** | 也没到上限 |

⇒ **「日期枚举无界 / 枚举到 2026年10月1日 这种不存在的日期」不是膨胀来源** ✗✓
（不存在的日期确实整节渲染，但每节只渲染一个 `EmptyState`：「输入内容，按 / 查看命令」——
在 cap=2 诊断构建的截图里 5 个空日期节**全都正常显示这一行** ✓）

### 2.6 第六步：**为什么恰好是 22,278 / 22,322**（量化）

**三点最小二乘**：`节点 ≈ 420 + 20.94 × 行数`

| 行数 | 模型预测 | 实测 | 误差 |
|---|---|---|---|
| 39 | 1,237 | 1,217 | −1.6 % |
| 209 | 4,797 | 4,817 | +0.4 % |

拆成上级要求的「N 天 × M 节 × K 节点/节」口径：
**7 天 × 1 节/天 × [ 外壳 60 + 块行 × 20.94 ]，其中 6 节几乎为 0、第 3 节值 ≈ 21,700** ✓

> 三点最小二乘 `Pss ≈ 118,612 + 629.4 × 行数` 对 K=30 点偏差 **+11 %** ⇒
> **节点数是干净的线性量，Pss 只能保证「单调、量级正确」** ✓

### 3.2 修法的核心（3 行）

```ts
private rowsForDisplay(): BlockData[] {
  if (this.embedded && this.rows.length > EMBEDDED_MAX_ROWS) {
    return this.rows.slice(0, EMBEDDED_MAX_ROWS);
  }
  return this.rows;
}
```

`refreshBlocks()` 把**交给 `LazyForEach` 的序列**换成它的返回值，并记录 `hiddenRowCount`。
**整页模式（`embedded=false`）原样返回 `this.rows`** ⇒ 文档页**零行为漂移** ✓

### 3.3 为什么这是「最小改动」（**方向由归因决定**）

归因结论是「**容器不虚拟化 ⇒ 行数无界 ⇒ 节点数无界**」⇒ 最小改动 = **给行数一个界** ✓。
逐条排除其它形态：

| 候选修法 | 为什么不采用（本窗口） |
|---|---|
| **把外层 `Scroll>Column>ForEach` 换成 `List>LazyForEach(days)`** ✗ | **不足以修复** ✓：外层只有 **7 个 item**，而第 3 个 item（`2026-09-30` 节）本身就是 1037 行高的**一个** item ⇒ `List` 仍会把它整体构建 ⇒ 节点数**几乎不降** ✗ |
| **给每节一个有界高度的内层 `List`** ✗ | 会引入 **`Scroll` 套 `List` 的双层滚动**（本仓在 S1-B 明确消除过双层滚动 ✗），且每节固定高度与「空日期只有一行」的语义冲突 ⇒ **改动面大、风险高** ✗ |
| **只渲染有内容的日期** ✗ | **实测无收益**：5 个空日期节各只值 1 个 `EmptyState`（约 10 个节点）✓ ⇒ 不解决问题，反而改变行为 ✓ |
| **给日期枚举收窄范围** ✗ | 前提被 2.1 证伪（枚举本来就只有 7 天）✓ |
| **✅ 每节行数上限 + 节尾入口** | **唯一同时满足「最小 / 不丢内容 / 不引双层滚动」的形态** ✓ |

### 3.4 内容不丢失（**为什么截断是可接受的**）

单日页的 `BlockList` 走 `List` + `LazyForEach`（**真虚拟化**，实测 1037 块只实例化 14 行）
⇒ **全部块都可浏览、可编辑** ✓ —— 只是**不在首页铺开** ✓

- **正常用户看不到它**：单日日志通常远小于 30 行（本 vault 9–16 行，从未触顶）。
