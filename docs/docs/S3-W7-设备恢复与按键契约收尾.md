**shell 身份**：`uid=2000(shell) gid=2000(shell) ... context=u:r:sh:s0`

#### 1.4.3 ★ 新发现：`__S1_long.md` 这个文件名**无法由应用产生** ✗

`entry/src/main/ets/core/models/Page.ets:92-129`：

```ts
const segments = sanitized.split('_');
const cleaned: string[] = [];
for (...) { if (seg === '' || seg === '.' || seg === '..') cleaned.push('_'); else cleaned.push(seg); }
let result = cleaned.join('_');
```

⇒ 页面名 `__S1_long` → `split('_')` = `['','','S1','long']` → 每个空段变成 `'_'`
⇒ `join('_')` = `'____S1_long'` ⇒ 落盘 **`____S1_long.md`**。

**设备侧印证** ✓：`graph/` 里实际出现的文件就是 **`____S1_long.md`**（0 字节），
而侧栏/标签页显示的是 **`__S1_long`**（页面名）。

⇒ **结论**：即使把"读不到文件"这一关解决，
**夹具也不可能以 `__S1_long.md` 这个名字被应用写进 vault** ✗。
凡「按文件名断言夹具」的验收，**必须**改用应用侧 pageName（`__S1_long`）/ 其落盘名（`____S1_long.md`），
或**改用别的文件名**（例如 `S1long` ⇒ `S1long.md`，无歧义）。

### 2.4 结论：**W6 的修复没有破坏跨块 ↑↓，而且补上了期望语义** ✓

W6 §10.5 的担心是「`BlockView.onGlobalFocusChanged` 补了『进入』分支后，
由代码写权威焦点的路径会**额外**让目标行进编辑态」。**实测确认这正是期望行为** ✓：
目标行**确实进了编辑态**（`RichEditor` 挂载、拿到键盘），
所以紧接着注入的字符能继续打进去 —— 这恰是 W5 §3 想达到而没达到的效果。

> ⚠️ **一条方法学纠正（给后续窗口）** ✗：W5 §1 的按键归属表里
> **`↑ = 2012`、`↓ = 2013`**。本窗口第一次误用 `2013` 当"上"，
> 打到了**最后一个块**上 ⇒ `focusAdjacentBlock(1)` 无邻居 ⇒ 无位移，
> **表现为"↑↓ 失效"** —— 极易误判成回归 ✗。
> **判据纪律：构造用例时必须保证目标方向上有邻居**（在最后一个块上按 `↓`、"无位移"是**正确行为**）。

### 4.3 ⚠️ 新观测：落盘比「5 s 硬截止」的预期晚

| 时刻 | 事件 |
